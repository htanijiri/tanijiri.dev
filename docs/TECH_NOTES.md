## 1. 技術選定
<!-- 何を選び、何を選ばなかったか、その理由。途中で乗り換えた場合はその経緯も書く -->

### ドメイン：Cloudflare Registrar で `tanijiri.dev` を取得
- 原価提供で、更新時に値上げされない（年 $12.20）。
- ホスティングを Cloudflare にする場合、ドメインの割り当てまで同じダッシュボードで完結する。
- 不採用：リンクまとめ系サービスの URL。サービス終了で URL ごと消えるリスクがあり、紙に刷る URL には使えない。

### ホスティング：Cloudflare Pages
- ドメインを Cloudflare で取得しているので、同じダッシュボードでドメイン割り当てまで完結する。Git 連携で push するとデプロイされ、HTTPS も標準で付く。
- 不採用：GitHub Pages（DNS の設定が Cloudflare 側に分かれる）、Cloudflare Workers の静的アセット配信（静的サイトならどちらでも動くので、Pages にした）。

### メール：Cloudflare Email Routing で受信、Gmail から送信
- 受信：`hiroshi@tanijiri.dev` を Cloudflare Email Routing で本名用の既存 Gmail に転送する。無料で、ドメインと同じダッシュボードで設定できる。転送先を変えても名刺は刷り直さずに済む。キャッチオール（どの宛先でも受ける）は無効のまま（迷惑メールが増えるため）。
- 送信：Gmail の「他のアドレスからメールを送信」で、Gmail の SMTP（`smtp.gmail.com:587`、Google のアプリパスワード）を使う。無料。独自ドメインの DKIM は付かず、受け手によっては「gmail.com 経由」と表示される。
- 切り替え先：Cloudflare Email Sending の SMTP（`smtp.mx.cloudflare.net:465`、API トークン認証、Workers Paid プラン）。2026-06 に SMTP に対応し、Gmail から独自ドメインの SPF・DKIM・DMARC がそろった状態で送れるようになった。それより前の記事は「Cloudflare では送信できない」と書いているので、日付に注意。
- 注意：Gmail の SMTP で送っている間は、DMARC を `p=quarantine` / `p=reject` にしない（独自ドメインの認証がそろわないので、自分のメールが弾かれる）。

### 静的サイトの作り方：素の HTML＋CSS（ビルドなし）
- 1ページ構成なら、ビルド工程も依存パッケージもないほうが、何年後に書き換えるときも迷わない（依存の更新やビルドの失敗で書き換えられない、が起きない）。
- 公開するファイルは `public/` に分ける。リポジトリ直下を公開すると、仕様書や CLAUDE.md まで配信される。
- 不採用：静的サイトジェネレーター（Astro、Eleventy など）。ページや Zenn 記事の自動取得を足すときに再検討する。

## 2. アーキテクチャ
- `public/` の静的ファイル（HTML 1枚、CSS 1枚、画像3枚、404 ページ）を Cloudflare Pages がそのまま配信する。ビルド工程も JavaScript もない。
- 初回表示の転送量は圧縮前で約 19KB（HTML・CSS・アイコン・favicon）。Lighthouse（モバイル、ローカル）は4項目とも 100（2026-09-30）。

## 3. ハマりどころと対処
<!-- 症状 → 原因 → 対処 の順で書く。CLAUDE.md の「消してはいけない設定」の理由はここに書く -->

### ヘッドレス Chrome で幅 360px のスクリーンショットが右で切れる
- 症状：`--window-size=360,...` で撮ると、文字が右端で切れて横にはみ出しているように見える。
- 原因：新しいヘッドレスモード（`--headless=new`）はウィンドウの幅を 500px 未満にできない。約 500px でレイアウトされた画面を、360px で切り取っている。
- 対処：幅 360px の `<iframe>` にページを入れた確認用ページを作って撮る。確認用ページは撮ったら消す（`public/` に残さない）。

### 色チェックが、正規表現のエラーで素通りしていた
- 症状：`scripts/check.sh` の色チェックで `grep: empty (sub)expression` と出るのに、結果は OK。
- 原因：macOS（BSD）の grep は、`-E` の正規表現の末尾が空の選択肢（`#FFF|`）だとエラーになる。エラーのとき出力が空になり、「4色以外の色はない」と判定されていた。
- 対処：空行は別の `grep -v '^$'` で除き、正規表現から空の選択肢をなくした。赤（`#ff0000`）をわざと混ぜて NG になることを確認した。

### 文言チェックが meta タグの中身で合格していた
- 症状：一行紹介を `<span>` で句ごとに分けても、「一行紹介がある」のチェックが OK のままだった。
- 原因：`meta description` に同じ文があり、HTML 全体を grep していた。
- 対処：`<body>` の中からタグを除いたテキストで確認するようにした。

### シェルスクリプトで、変数の直後の全角文字が変数名に取り込まれる
- 症状：`echo "…（$BASE）"` が `BASE�: unbound variable` で止まる（`set -u` のとき）。
- 原因：bash が全角文字の先頭バイトを変数名の一部として読む。
- 対処：日本語の直前・直後の変数は必ず `${BASE}` と波かっこで囲む。`LC_ALL=C grep -nE '\$[A-Za-z_][A-Za-z0-9_]*[^ -~]' scripts/*.sh` で残りを探せる。

### 確認スクリプトが、サーバーの起動前に走って全部 NG になった
- 症状：ページは正しいのに、HTML の中身を見る項目だけがすべて NG。
- 原因：ローカルサーバーの起動を待たずに確認を始め、空の HTML を受け取っていた。
- 対処：`scripts/check.sh` は、トップページか CSS が空なら確認をせずに終了コード 2 で止まる。

### sips で縮小した PNG に EXIF が付く
- 症状：`sips -z` で作った PNG に `eXIf` と `cHRM` のチャンクが入る（元画像にはない）。
- 対処：`scripts/make-icons.sh` の中で取り除く。中身は解像度などで個人情報ではないが、配信には不要。

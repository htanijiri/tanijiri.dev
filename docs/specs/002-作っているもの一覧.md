# 002 作っているもの一覧

- 状態：完了
- 依存：001

## 背景・課題
名刺から来た人がいちばん見たいのは「この人が何を作っているか」で、ここがサイトの本体になる。
一行紹介「自分が使うものを、自分でつくるのが好きです。」を、具体的な作ったものの一覧で裏付けたい。作ったものは増えたり変わったりするので、追加・更新が楽である必要がある。

## ゴール
- トップページに「作っているもの」のセクションがあり、個人開発物が一覧で並ぶ。
- 各項目は、名前・一行の説明（何のために、何を解決するか）・リンク・関連する Zenn の記事（あれば）を持つ。
- 説明の文言は「自分が使うために作った」というトーンに揃える（技術の自慢より、何に困って何を手に入れたか）。
- 項目の追加・並べ替え・削除が、1か所（HTML の該当部分、またはデータファイル）の編集で済む。

## やらないこと
- 各作品の詳細ページ（1ページ構成から始める。必要になったら別の仕様書で足す）。
- カテゴリ分け・状態の表示・スクリーンショット（件数が増えたら見直す）。
- Zenn の記事一覧の自動取得（フェーズ2で検討）。
- GitHub のリポジトリ一覧の自動取得（掲載するものは自分で選ぶ）。
- 業務で作ったもの、勤務先・客先に関係するものの掲載。

## 設計方針
- 1項目＝名前・説明・リンク（GitHub）・関連する Zenn の記事（あれば1本）の組。カテゴリや状態の表示はしない。「ハッカソンで作った」などは説明文に書く。
- 並び順は掲載データの順番どおりにする（自動で並べ替えない）。
- 画像（スクリーンショット）は使わない。デモ動画があるものは説明文からリンクする。
- 素の HTML なので、`public/index.html` の該当部分に項目を直接書く（1項目＝同じ形の HTML のまとまり）。

## 検討した案と不採用の理由
| 案 | 採用 | 理由 |
|---|---|---|
| 掲載項目を手で選んで書く | 採用 | 何を見せるかを自分で決めたい。業務に関係するものが混ざらないようにする。 |
| GitHub API でリポジトリ一覧を自動表示 | 不採用 | 掲載したくないリポジトリも出る。説明のトーンも揃えられない。 |

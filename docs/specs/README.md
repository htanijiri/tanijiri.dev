# 仕様書（docs/specs）

機能追加・変更は、相談した結果をここに**1機能＝1ファイル**でまとめてから実装する。
実装する Claude にとっての「ゴールと完了条件」になる文書なので、曖昧さを残さない。

## 運用ルール
- ファイル名は `NNN-機能名.md`（3桁の連番）。新規作成は [_template.md](_template.md) をコピーする。
- 状態は `ドラフト` → `合意済み` → `実装中` → `完了`（やめた場合は `見送り`）。
  **`合意済み` になるまで実装に着手しない。** 状態を `合意済み` にするのはユーザー。
- 受け入れ条件は、テストやコマンドで確認できる形で書く。「いい感じに」「適切に」は書かない。
- 実装中に仕様が変わったら、先に仕様書を直してから実装を続ける（仕様書と実装を食い違わせない）。
- 完了したら、得られた知見を [TECH_NOTES.md](../TECH_NOTES.md) に還元する。
- 公開リポジトリにする場合、仕様書も公開される。個人情報・社内の固有名詞・実際のパスは書かず、例は架空のもので書く。
